# NxMonitor 功能说明与产品约定

本文件说明产品要做什么、目前做到哪里。用户确认的范围以 [requirements.md](requirements.md) 为基线；开发优先级和验收拆分见 [ROADMAP.md](ROADMAP.md)。这里的“待做”不是已经提供的功能。

## 1. 产品定位

NxMonitor 是面向 Windows 的非注入式性能 HUD，用于在游戏或图形应用运行时查看 FPS、帧时间及相关资源信息。目标是紧凑、低干扰、可定制，而不是大型仪表盘。

- 技术栈：Rust + GPUI-Kit。用户看过静态参考样板后接受效果，选择继续 GPUI-Kit；没有决定迁移 Tauri 2 / SolidJS。
- 产品名、仓库工作目录名：NxMonitor。
- 用途：自用并计划开源。项目自身开源许可证尚未选定。
- 首版目标平台：Windows 10 / 11，x64；当前最低实测基线 Windows 10 22H2（19045）。不承诺 Windows 10 所有旧版本或 ARM64。
- 语言：中文、英文。

## 3. 目标选择与会话

### 自动模式

1. 取得前台窗口对应进程，读取其路径与启动时间。
2. 排除 NxMonitor 自身、系统PID、不可识别候选、黑名单。
3. 候选稳定约650ms后切换，减少短暂窗口激活引发的抖动。
4. 用户激活 NxMonitor 设置/HUD 时，保留仍然有效且未被排除的当前目标。
5. 切换目标结束旧采集并清空旧统计；新目标开启新会话，不能混算。

当前按可见窗口进程发现，未实现启动器→游戏子进程识别、游戏数据库或可选主交换链UI。

### 手动模式

- 在设置窗口按名称/PID筛选并锁定目标。
- 锁定绑定 `(PID, 启动时间)`；不能仅凭PID持续追踪。
- 手动锁定不随前台切换，目标退出后等待重新选择。
- 切回自动时清除旧手动锁定，再切手动不能静默恢复。
- 重启只恢复路径提示，不自动恢复旧PID或同路径新进程。

### 黑名单

- 支持文件名、完整Windows路径两类规则；不支持通配符。
- 文件名当前使用ASCII大小写无关比较；完整路径规范分隔符并转小写比较。不是Windows文件身份/符号链接解析器，后续如支持非ASCII大小写或路径别名需补测试。
- 只影响自动选择；手动选择命中项必须出现明确确认/取消。
- 不宣称黑名单能阻止底层ETW后端接触所有相关系统事件。
- 当前配置最多256条规则。

## 4. FPS 指标与显示语义

| 指标 | 当前定义 |
| --- | --- |
| 呈现FPS | 来自目标交换链相邻Present调用间隔，不保证每帧都实际上屏 |
| 当前FPS | 当前显示链最近约1秒有效帧间隔的聚合倒数 |
| 当前帧时间 | 同一批有效间隔的平均ms，不由取整FPS反算 |
| 平均FPS | `1000 × 样本数 / 总帧时间ms`，不是逐帧FPS算术平均 |
| 最低/最高FPS | 排除首尾不完整秒后的完整1秒帧计数桶极值，可包含0帧完整秒 |
| 1% low | 最慢 `ceil(n×0.01)` 个间隔的平均倒数，至少100样本 |
| 0.1% low | 最慢 `ceil(n×0.001)` 个间隔的平均倒数，至少1000样本 |
| 滚动统计 | 默认最近30秒；用户可调范围是首版目标，当前尚未暴露配置 |
| 会话统计 | 从当前链采集开始到重置/切换；当前仅会话平均进入HUD |

- 同PID多交换链分别统计。当前以共同最新一秒内样本最多的链作为显示链，是启发式，可能切换。
- 缺数据、等待、过期、采集失败、目标退出、样本不足不能伪装成正常0值。
- 当前原型间隔与历史窗口随事件推进；无新帧时HUD实时值标不可用。完成真正时间窗口/无限会话时需处理长暂停和过期语义。
- 性能录制、CSV用户导出不在首版范围。后端内部CSV传输不等于导出功能。

## 5. 资源和音频

### 内存与设备

- 系统内存、目标进程内存、基础设备信息属于首版。
- 当前内存：GlobalMemoryStatusEx的总量减可用量=系统已用物理；K32GetProcessMemoryInfo的WorkingSetSize=目标工作集。不是私有字节；约1秒后台采样、最多60次尝试历史，失败为缺口，超过3秒标过期。目标切换清空进程历史，系统历史继续。
- 设备清单启动缓存：CPU型号/物理核心/逻辑处理器、Windows build/release/edition与架构、DXGI硬件适配器名称及VEN/DEV/LUID。GPU清单不是目标GPU归属。显示器为目标所在屏幕（无目标时主屏），含编号、分辨率和系统报告整数Hz；窗口是客户区物理像素，最小化/无窗口/失败/过期明确不可用。未检测目标图形API。
- Graphy的 `reserved/allocated/mono` 属于Unity Profiler，不能直接照搬为Windows实时指标。
- CPU/GPU使用率、显存和温度不因截图出现类似字段而自动加入当前任务；温度单独评估。

### 系统音频

- 首版监测整机播放输出，提供电平和频谱，默认跟随系统播放设备。
- dBFS是数字音频电平，不是环境声压、扬声器真实响度或分贝仪。
- 音频采样、RMS/FFT与UI绘制分离；静音、无设备、切换设备、权限/采集失败有明确状态。
- 目标进程音频、麦克风、录音存盘不在当前首版已确认范围；进程级输出后续验证。

## 6. 视觉与交互

- Graphy预设：紧凑暗色半透明、密集图表、阈值线、多曲线填充和频谱峰值保持。
- modern预设：相同能力，采用更清楚的原生层级和设置交互。切换不重置目标和统计。
- 用户已接受静态样板方向，不需要继续做框架对比或迁移。后续在实际数据视图中整合，不把示例数据接入实时HUD。
- 静态样板入口 `nxmonitor-ui-reference` 中的内存/音频/设备式文字是视觉示例，不是Windows指标实现；背景是代码绘制的抽象替代，不是原游戏场景。
- 需要整体拖动、四角锚点、边距、多屏、缩放和显示模块开关；不做内部控件任意重排编辑器。
- 设置采用GPUI-Kit标准语义控件，键盘/焦点/禁用/错误路径也属于验收。

## 7. 权限、兼容性与发行

- 非注入优先、普通权限优先；不自动请求UAC，不绕过反作弊，不安装隐蔽驱动/服务。
- 权限不足需明确说明；后续若实现提权入口必须由用户显式触发。
- “能采集”与“HUD能覆盖目标”分开验收；优先窗口和无边框全屏，独占全屏单独验证，不预先保证。
- Windows11、真实游戏、DPI/多屏、发布版开销仍需各自环境证据。
- 开源前选择项目许可证，完成依赖/字体/文档的通知与分发核对，见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。
