# NxMonitor 首版需求基线

状态：用户已确认的首版范围。需求基线不等同于全部已实现；当前功能/进度分别见 [PRODUCT.md](PRODUCT.md)、[STATUS.md](STATUS.md)，整体任务与验收见 [ROADMAP.md](ROADMAP.md)。

## 定位与平台

- Rust + GPUI-Kit，产品及工作区名称 NxMonitor；自用并准备开源。
- Windows 10 / Windows 11，首版 x64。Windows 10 22H2 为当前最低验证基线；Windows 11 必须另行实测。
- 中英双语。开源分发前核定所有依赖及素材许可；项目自身许可证尚未指定。

## 目标选择与采集

- 自动识别前台游戏/图形应用；允许手动选择并锁定一个进程，锁定时不随前台切换。可切回自动模式。
- 设置包含黑名单：默认按可执行文件完整路径匹配，也允许文件名匹配；只影响自动选择。
- 黑名单中的进程允许手动选择，提示后继续；不将黑名单描述为底层全局事件绝不采集的保证。
- 优先非注入、普通权限运行；采集确需权限时明确提示提权，不默认开机提权，不绕过反作弊限制。
- 优先确保普通窗口与无边框全屏；独占全屏单独验证。数据采集与 HUD 能否覆盖分开验收。
- 不使用应用自身刷新率或模拟数据冒充目标游戏 FPS；无数据、权限不足、退出、失败必须可区分。

## FPS 与统计

- 当前 FPS、当前帧时间 ms、平均 FPS、最低/最高 FPS、1% low、0.1% low。
- FPS 历史图、帧时间历史图。
- 最近滚动窗口默认 30 秒，可配置；同时提供整段会话统计，两个口径有明确标签。
- 切换目标开启新会话；支持手动重置。最低/最高按完整 1 秒时间桶计算，非单帧 FPS 极值。
- 平均值按帧数 / 总帧时间计算；low 使用最慢比例的帧时间聚合，文档明确算法及样本量要求。
- low 样本不足显示不可用，不填 0；当前 ms 不由已取整的显示 FPS 反算。
- 首版不做性能录制与 CSV 导出；内部使用采集器 CSV 作为传输格式不等于用户导出功能。

## 资源、设备与音频

- 首版：系统内存、目标进程内存、CPU/GPU/OS/屏幕等基础设备信息。指标名称明确区分总量、占用、工作集等。
- CPU/GPU 温度后续单独评估；不把 Unity reserved/allocated/mono 直接映射到 Windows。
- 系统播放输出电平（dBFS，非环境声压）和频谱，默认跟随播放设备。
- 进程级音频后续单独验证。

## 外观与桌面能力

- 可选择 Graphy 式紧凑 HUD 或现代原生 HUD；功能一致，切换风格不重置目标、位置、模块和统计。
- 独立设置窗口；语义主题、数字稳定对齐、相对尺度、原生控件与完整键盘路径。
- 始终置顶；鼠标穿透；进入编辑模式后拖动 HUD 整体；四角吸附与边距。
- 字体、缩放、透明度、颜色设置；模块开关；全局显隐快捷键；托盘；开机启动；多显示器选择。
- 首版不做内部控件任意重排的自由布局编辑器。

## 初始阶段：最小技术验证（历史范围）

1. 核定 GPUI-Kit 版本、许可、Windows 原生构建条件。
2. 用真实外部进程帧事件计算 FPS，明确呈现/显示口径与权限限制。
3. 创建 GPUI-Kit HUD，验证透明、置顶、穿透和编辑模式切换；验证结果与未测能力分别记录。
4. 统计逻辑和解析边界可独立测试；不因 UI 采样率改变原始统计。

以上是初始PoC阶段范围，不是当前完成状态：此后已完成基础目标选择/黑名单/独立设置与配置闭环。托盘、音频、资源监测等仍待做；Windows11、真实游戏/反作弊、全屏和多屏需要分别验收。换电脑从 [DEVELOPMENT.md](DEVELOPMENT.md) 与 [TESTING.md](TESTING.md) 接续。
