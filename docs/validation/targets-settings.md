# 目标选择与设置闭环验证

## 本轮范围

在已有 GPUI-Kit 原生 HUD / PresentMon 采集基础上，新增 `nxmonitor-desktop` 入口，实现目标选择、自动选择黑名单、独立设置窗口和本地配置持久化。静态 Graphy 样板已停止调整，保留独立入口；本轮不实现内存、设备信息、音频、托盘、开机启动和多屏。

## 使用入口

```powershell
$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"
cargo build --locked --features hud --bin nxmonitor-desktop -j 1
.\scripts\Get-PresentMon.ps1
.\target\debug\nxmonitor-desktop.exe
```

- 默认配置：`%LOCALAPPDATA%\NxMonitor\settings.json`。
- 隔离测试：`--config C:\path\settings.json`；相对配置路径需包含父目录，例如 `--config .\settings.json`。
- `--list-processes` 输出可识别的可见窗口应用。
- `--capture-seconds 1..600` 设置当前有界验证会话时长，默认600秒；到期在设置中重新采集。
- `--smoke-seconds N` 自动关闭，用于原生窗口 smoke test。
- 默认打开 HUD + 设置。关闭设置不退出 HUD；进入 HUD 编辑模式后可重新打开设置。退出按钮/全局退出结束整个程序。

## 规则与实现

### 目标选择

- 自动模式以稳定前台应用为候选，约650ms防抖；进程需有可见顶层窗口并允许只读身份查询。
- 使用 Windows `PROCESS_QUERY_LIMITED_INFORMATION`、进程创建时间和可执行路径；不注入、不改目标进程。
- 自动选择排除自身、系统PID及黑名单。切到 NxMonitor 自身设置/HUD 时保留仍然有效且未被排除的目标。
- 手动锁定绑定 PID + 创建时间，不跟随前台变化；目标退出或 PID 被复用不自动转移锁定。
- 从手动切到自动会清除旧手动锁定，再切手动必须重新选择；防止旧黑名单目标绕过覆盖确认。
- 保存手动路径仅用作重启后的提示，不保存PID、不自动重锁。
- 目标变化时在后台停止旧采集、清空快照、建立新会话；UI不会消费旧采集线程的数据。

### 黑名单与设置

- 支持文件名/完整Windows路径两种规则，精确匹配、规范路径分隔符，不支持通配符。
- 规则只影响自动选择；手动选择黑名单目标显示“仍然锁定/取消”确认。
- 保存模式、路径提示、黑名单、语言、风格、采集器路径。样例HUD中的内存/音频占位没有进入真实HUD。
- 设置用标准 GPUI-Kit Input、RadioGroup、Switch、Button 和 Scrollable，状态拥有者不在 render 中重建。
- 相对采集器路径按项目开发目录/应用目录解析，而不是依赖启动工作目录。
- 配置版本1；校验后使用同目录临时文件原子替换；无效配置保存不会覆盖上一次有效文件。
- UTF-8 BOM 文件可恢复；配置损坏时原文件保留、禁止保存覆盖，安全回退到未选择目标的手动模式，不自动采集。
- 控制器队列先预留容量，再原子保存、发布命令；队列满不写盘，保存失败不入队，避免磁盘/界面分叉。

## 验证环境

Windows 10 Pro 22H2 19045 x64，Rust 1.96 MSVC，GPUI-Kit 0.8.0，PresentMon 2.6.0 x64。本轮实测使用 scratch 内独立配置文件，没有写默认用户配置，也没有修改系统用户组/请求自动提权。

## 自动检查

- `cargo fmt --all -- --check`：通过。
- `cargo test --locked --features hud --all-targets -j 1`：**20项通过**，包含12项既有采集/统计测试、7项目标/配置集成测试、1项配置提交回归测试。
- `cargo clippy --locked --features hud --all-targets -- -D warnings`：通过。
- 桌面入口构建通过；本机曾出现并行测试缺失依赖元数据缓存，单任务测试构建恢复并通过，不是测试断言失败。

### 核心测试覆盖

- 自动跟随前台、排除自身/系统/未知路径/黑名单。
- 手动不跟随前台，目标退出、PID复用、重启路径提示不重锁。
- Windows文件名/路径匹配与规则校验。
- 默认配置、往返保存、Windows覆盖原子替换、无效保存保护、损坏JSON保护、UTF-8 BOM兼容。
- 配置提交：队列满时不执行保存；保存失败时不发布命令；成功只入队一次。

## 原生窗口与真实采集实测

使用 Windows UI Automation 的实际控件 role/name/value/selected/toggle 状态操作设置；每次操作重新定位控件，并滚动到原生窗口可见范围后再执行。Switch 使用 TogglePattern，而不是伪造点击。测试不向游戏发送鼠标/键盘，只在自动模式测试中激活其前台窗口。

通过的流程：

1. 设置窗口打开，进程名称/PID筛选可用。
2. 手动锁定外部 `RobloxStudioBeta.exe`（测试时PID21444），开启真实 PresentMon 会话。
3. 添加 `RobloxStudioBeta.exe` 文件名黑名单并保存，已手动锁定会话不因黑名单添加而重启。
4. 切自动后，把该目标窗口置前台；没有开启第二条自动采集会话。
5. 自动再切手动，没有恢复旧锁定；重新点击锁定黑名单目标时必须确认，取消不改变模式，确认开启新会话。
6. 语言切换中英、Graphy预设开关保存成功；UI即时反映设置。
7. 重置采集开启新会话；最终一次UI流程退出前收到444条真实帧。
8. 正常退出后无本程序PresentMon子进程及唯一命名ETW会话遗留。
9. 单独自动跟随测试：前台外部Studio成功选择，收到6276条真实帧；激活NxMonitor设置未重建会话；退出清理通过。
10. 重启已保存配置恢复语言、风格和黑名单，手动模式没有旧PID重锁，也未改写只读恢复的配置内容。
11. 损坏配置实际窗口测试：错误状态可进入安全设置，未创建采集会话，退出后原始字节完全保留。

这些数字是不同测试运行中的事件计数，不是性能基准。目标为Studio窗口，不代表已验证任意游戏、反作弊、全屏或Windows11。

## 本轮发现与修复

- 原生无障碍树将窗口外控件标为可见，离屏 Invoke 未触发“添加”；改为真实几何可见范围滚动后，业务保存正确，未为测试改变业务规则。
- PowerShell写出的BOM配置最初不能解析：加载器增加BOM兼容和回归测试。
- 单次只读审阅发现旧手动锁定可能绕过确认、保存后命令队列拒收可能状态分叉：均已修复并重测。
- 提前/空帧退出时ETW清理等待过短：只停止本次唯一命名会话，扩大正常退出等待，必要时再次清理；自动与手动原生流程均验证退出后无遗留。强制结束/崩溃仍不等同于正常退出保证。

## 当前限制与下一阶段

- 自动候选是前台可见窗口进程，不是完整游戏数据库/启动器子进程识别；可用黑名单和手动锁定纠正。
- 当前每次会话仍有600秒上限，统计保留既有原型内存限制；尚未完成无限会话、性能优化和发布构建验收。
- 正式HUD仅FPS数据；未完整套用已接受的静态Graphy样板，也未接入内存/音频等区域。静态数据从未作为实时读数展示。
- 设置仅当前阶段字段；窗口位置、字体、颜色、透明度、模块开关等完整持久化仍待实现。
- Windows11、无边框/独占全屏、反作弊、多屏/DPI与完整辅助功能流程未验收。
- 尚无安装器、CI或项目自身开源许可证；工作区原本不是Git仓库，本轮没有初始化仓库、提交或推送。

本阶段目标选择/设置闭环无剩余阻塞。下一阶段应接入系统/目标进程内存与设备信息，再做系统音频电平/频谱，并把已接受的HUD视觉整合到真实数据视图。
